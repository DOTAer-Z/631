# new_pipeline 数据创建总结

## 概述

新版数据处理流水线创建了四层存储架构：

1. **MySQL** - 元数据层 / 任务层 / 结果层
2. **MongoDB** - 证据层
3. **FAISS** - 独立向量库
4. **文件系统** - 知识图谱导出

---

## 脚本修改说明（2026-03-20）

### 问题背景
原始数据流中，log_windows 和 FAISS 向量库的 metadata 缺少 `fault_type`、`root_cause`、`root_cause_type` 字段，导致检索阶段无法获取故障标签信息，KG 推理结果为空。

### 修改内容

#### 1. 04_build_log_windows_v2.py
**新增功能**：
- 从 MySQL `diagnosis_results` 和 `cases` 表补查故障标签字段
- 将标签字段写入 log_windows 文档的顶层
- 同时写入 `metadata` 子字段，便于后续统一读取

**修改细节**：
- 新增 `fetch_mysql_labels()` 函数：按优先级查询 diagnosis_results → cases
- 修改 `get_run_meta()` 函数：合并 MySQL 标签数据
- 修改 `build_window_doc()` 函数：在文档顶层和 metadata 子字段中都包含标签
- 新增索引：`idx_windows_task: (task_id)`

**数据流变化**：
```
MySQL diagnosis_results/cases
    ↓ (查询 fault_type, root_cause, root_cause_type)
MongoDB log_windows
    ├─ 顶层字段：fault_type, root_cause, root_cause_type
    └─ metadata 子字段：包含上述字段 + 其他元信息
```

#### 2. 05_build_vector_index_faiss.py
**新增功能**：
- 从 log_windows 读取标签字段（兼容顶层和 metadata 子字段）
- 将标签字段写入 FAISS metadata.jsonl
- 统计标签字段非空数量

**修改细节**：
- 新增 `get_label_field()` 函数：兼容两种字段来源
- 修改 `fetch_windows_batch()` 的 projection：包含标签字段和 metadata
- 修改 metadata 构建逻辑：写入 fault_type, root_cause, root_cause_type
- build_info.json 新增 `label_stats` 字段：统计非空标签数量

**数据流变化**：
```
MongoDB log_windows (包含标签字段)
    ↓ (读取 fault_type, root_cause, root_cause_type)
FAISS metadata.jsonl
    └─ 包含完整的故障标签信息
```

#### 3. 06_build_knowledge_graph.py
**说明**：
- 该脚本从 MySQL 的 cases 和 diagnosis_results 表获取故障标签信息
- 通过 case_fault_map 和 task_fault_map 建立 LogWindow → FaultType 的关联
- 不直接从 log_windows 读取标签字段（因为已通过 MySQL 获取）

**数据流**：
```
MySQL cases / diagnosis_results
    ↓ (构建 case_fault_map 和 task_fault_map)
MongoDB log_windows
    ↓ (通过 case_id / task_id 关联)
KG LogWindow 节点
    └─ 通过 SUPPORTS_FAULT 边关联到 FaultType
```

## 知识图谱导出文件

### 输出文件结构
```
<out-dir>/
├── kg_nodes.jsonl       # 节点文件（每行一个节点）
├── kg_edges.jsonl       # 边文件（每行一条边）
└── kg_summary.json       # 摘要信息
```

### kg_nodes.jsonl 格式
```json
{
  "id": "System::openstack",
  "type": "System",
  "properties": {
    "system_id": "openstack",
    "name": "OpenStack",
    "code": "openstack"
  }
}
```

**节点类型**:
- `System`: 系统
- `Subsystem`: 子系统
- `Component`: 组件
- `Case`: 测试用例
- `Run`: 运行轮次
- `Task`: 诊断任务
- `FaultType`: 故障类型
- `RootCause`: 根因
- `LogWindow`: 日志窗口

### kg_edges.jsonl 格式
```json
{
  "source": "System::openstack",
  "relation": "HAS_SUBSYSTEM",
  "target": "Subsystem::1"
}
```

**边类型**:
- `HAS_SUBSYSTEM`: System → Subsystem
- `HAS_COMPONENT`: Subsystem → Component
- `HAS_CASE`: Subsystem → Case
- `HAS_RUN`: Case → Run
- `HAS_TASK`: Run → Task
- `HAS_RESULT_FAULT`: Task → FaultType
- `HAS_ROOT_CAUSE`: Task → RootCause
- `TARGETS_COMPONENT`: Case/Task → Component
- `HAS_WINDOW`: Run → LogWindow
- `USES_WINDOW`: Task → LogWindow
- `SUPPORTS_FAULT`: LogWindow → FaultType

### kg_summary.json 格式

## 数据层次结构

## 数据量估算

 OpenStack 数据集（480 个测试，每个测试 2 个轮次）：

| 数据类型 | 预估数量 | 说明 |
|---------|---------|------|
| MySQL systems | 1 | openstack |
| MySQL subsystems | 3 | Nova, Cinder, Neutron |
| MySQL components | ~480 | 每个测试的目标组件 |
| MySQL cases | 480 | Nova(231) + Cinder(125) + Neutron(124) |
| MySQL runs | 960 | 每个 case 2 个轮次 |
| MySQL diagnosis_tasks | 960 | 每个 run 一个任务 |
| MySQL diagnosis_results | 960 | 黄金结果 |
| MongoDB log_entries | 数百万 | 取决于日志量 |
| MongoDB log_windows | 数万 | 取决于窗口策略 |
| FAISS vectors | 数万 | 与 log_windows 一一对应 |
| KG nodes | ~1.3万 | 包含所有实体 |
